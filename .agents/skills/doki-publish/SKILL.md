# Doki 发布流程

1. 在含 `package.json`、`extension/manifest.json` 和此 Skill 的 Doki 仓库中工作。首次使用按仓库 [README](../../../README.md)启动工作台并连接 Chrome 插件。无需上传或索取配对码、密码或 Cookie。
2. 确定目标平台和内容类型。以用户提供的真实素材、实测和事实核对标题、正文、话题。区分准备草稿、排队、交接、已发表四种状态。素材缺失时可以先在网页建草稿，向用户说明需要补齐什么。
3. 图文按展示顺序整理正文图，首图用作首屏。视频使用成片和可选封面。每个平台单独准备一份清单，保留平台化文案。发布格式、数据字段和操作顺序见 [工作流程](../../../docs/workflow.md)。
4. 用 `npm run doki -- import <任务.json>` 导入草稿。用户明确要求排入队列时加 `--queue`，或对现有草稿运行 `npm run doki -- queue <ID>`。失败先用 `status <ID>` 检查，再按 CLI 返回的 `--resume <ID>` 续传。排期需含时区。
5. 让用户从插件取任务，在当前平台选入素材，预填可识别的标题和正文。检查实际话题、封面、时间、原创或 AI 声明及可见范围，再到平台完成提交。平台最终提交由用户执行。
6. 只有用户确认已交接时才记录交接。拿到用户提供的已发布作品链接后用插件或 `npm run doki -- publish <ID> <作品链接>` 回填。视频号无可复制链接时可按用户确认记录。平台显示审核中或定时时保持待回填。

交付时报告平台、类型、素材数量、任务 ID、当前状态及下一项人工操作。仅使用用户给定的内容和授权范围。
